# DOPIS-LEARNING-009 — Vertical-slice boundaries and dependency justification

- Observation: independent review of the PLAN-004 vertical-slice model found four defects: (1) the traceability contract promised that an additional, non-induced slice dependency must carry a source-backed rationale, but the model represented `dependencies` as bare slice-id strings and the validator accepted any additional valid id without checking for one; (2) `VS-ORDERING-001` bundled the optional, independently disableable `ST-UPSELL-001` recommendation behavior into the core catalog/checkout outcome; (3) `VS-CAPACITY-001` recombined the deliberately separated permanent/planned capacity authority (`ST-CAPACITY-001`, Jaime-only) with temporary current-service capacity authority (`ST-CAPACITY-002`, `ST-CAPACITY-003`); (4) the deferred SMS-provider baseline reference (`TB-INTEGRATION-003`) was missing from `VS-KITCHEN-001`, whose accepted ready-notification behavior actually encounters it, and was instead attached to `VS-PILOT-001`, which does not own SMS provisioning.
- Impact: a contract invariant the validator could not check would have let an unjustified hard dependency pass silently; the ordering bundle would have forced an optional, disableable upsell behavior to ship or roll back only together with core checkout; the capacity recombination would have blurred a deliberate authority boundary between Jaime's normal-service plan and staff/responsible-person temporary controls; the SMS reference drift would have hidden the real dependency (kitchen ready-notification) behind an unrelated later milestone slice (pilot).
- Cause: slice grouping and dependency representation were checked for story coverage and induced-dependency completeness, but not against each slice's own acceptance/rollback/product-learning boundary, not against the actor/authority separations already deliberate in the accepted stories, and not against which slice's accepted behavior actually encounters a given deferred technical reference; and the traceability contract declared a machine-checkable invariant without an accompanying validator rule or fixture proving it was enforced.
- Containment: preserved every other accepted slice grouping, all 27 product acceptance-criteria coverage through story membership, the two existing induced dependencies (`VS-TRACKING-001 -> VS-ORDERING-001`, `VS-COLLECTION-001 -> VS-KITCHEN-001`), `NOT_GRANTED` implementation authority, and `NOT_STARTED` technical-contract/ADR/test/task/execution-packet planning; changed no requirement, story, use case, acceptance criterion, minimum technical baseline, or application code.
- Correction: added a `dependency_rationale` field (target slice id -> non-empty rationale plus concrete accepted `source_refs`) to the vertical-slice model and its contract, and added validator checks (`unjustified_additional_slice_dependencies`, `dependency_rationale_for_undeclared_dependency`, `invalid_dependency_rationale_entries`) that deterministically reject a non-induced dependency lacking a valid entry, with a negative fixture and a passing positive/control fixture in `scripts/test_validate_specification.py`; split `ST-UPSELL-001` into its own `VS-UPSELL-001` slice depending on `VS-ORDERING-001` through a justified rationale; split `VS-CAPACITY-001` into a Jaime-only planned-capacity slice and a new `VS-CAPACITY-CONTROL-001` temporary current-service slice (`ST-CAPACITY-002`, `ST-CAPACITY-003`) depending on it through a justified rationale; moved `TB-INTEGRATION-003` from `VS-PILOT-001` to `VS-KITCHEN-001` while leaving it on `VS-TRACKING-001`.
- Prevention: review slice grouping against acceptance, rollback, and authority boundaries (not just story/requirement coverage), and review every declared traceability-contract invariant against actual, tested validator behavior before treating the contract as enforced; place a deferred technical-baseline reference on the slice whose accepted behavior actually encounters it, not a later generic milestone slice.
- Evidence limits: this record corrects vertical-slice grouping, dependency representation, and deferred-reference placement only; it invents no requirement, story, or acceptance criterion, and grants no implementation, ADR, test, task, or execution-packet authority.
- Validation plan: run the locked GOV-GEN consumer validator, `scripts/validate_specification.py`, `scripts/test_validate_specification.py`, and confirm slice/story coverage, actor and readiness-gate unions, acyclic dependencies, induced-vs-additional dependency distinction and enforcement, deferred-reference resolution, `future_nodes.vertical_slices` exactness, and `git diff --check`.
